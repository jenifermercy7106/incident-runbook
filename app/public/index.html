Incident Response Runbook

Quick playbooks for common DevOps incidents

Server Down
  1. Confirm the outage (ping, curl the health URL).
  2. Check if the server or VM is running in the cloud console.
  3. Check recent deployments or changes.
  4. Restart the service and watch the logs.
  5. Notify the team and write down the timeline.
High CPU Usage
  1. Find the busy process (top / htop).
  2. Check if traffic suddenly increased.
  3. Look at application logs for errors or loops.
  4. Scale up or restart the affected service.
  5. Record the root cause after recovery.
Deployment Failed
  1. Check the pipeline logs to see which stage failed.
  2. Verify the Docker image built and pushed correctly.
  3. Check Kubernetes pods (kubectl get pods, kubectl describe pod).
  4. Roll back to the last working version.
  5. Fix the issue and redeploy.
